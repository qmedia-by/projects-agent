# projects-agent

Инструкции и скиллы для агента, который отвечает на вопросы о проектах qmedia: что с проектом, что горит, куда ушли часы, что обсуждали с клиентом. Данные даёт MCP-сервер `projects-mcp` — задачи Битрикс24, таймшит и переписка в Telegram; агент их только читает.

Менеджеры работают в одной Среде — VS Code с расширением Codex. Репозиторий публичный: секретов, названий клиентских проектов и имён людей в нём нет. Вход на сервер — через Google, а кого пускать, решает список менеджеров на сервере.

## Для Менеджера

- [Настройка](docs/manager-setup.md) — один раз, минут двадцать.
- [Инструкция](docs/manager-guide.md) — типовые вопросы и что делать при ошибках.

## Что умеет

```text
Что с проектом example.by?
```

```text
Что горит у меня? Моя фамилия в листе «Проекты» — Иванов.
```

```text
Сколько часов ушло на example.by в августе, по типам работ?
```

```text
Что клиент example.by писал про оплату в сентябре?
```

Агент ничего не меняет ни в Битриксе, ни в таблице, ни в переписке. Сделки CRM не подключены, разреза часов по сотрудникам нет.

## Как устроено

| Что | Где |
|---|---|
| MCP-сервер | `https://projects-mcp.tech.qmedia.by/mcp`, репозиторий `qmedia-by/projects-mcp` |
| Конфиг сервера для Codex | `.codex/config.toml` — только адрес, без ключей |
| Правила агента | `AGENTS.md`, термины — `CONTEXT.md` |
| Скиллы | `.agents/skills/` |
| Автообновление | `.codex/hooks.json` → `.codex/update-check.sh`, на Windows `.ps1` |

Менеджеры сидят на ветке `dev`: всё, что туда попадает, приходит к каждому в начале следующего чата.

## Разработка

Проверки перед PR:

```bash
npm test
```

`lint-skills.mjs` следит за структурой скиллов, `test-skill-rules.mjs` — за тем, что несущие правила не выпали из текста, `check-config.mjs` — за тем, что конфиг указывает на сервер, не содержит ключей и `hooks.json` не менялся. Где живёт какой факт и порядок правки — [docs/changing-this-repo.md](docs/changing-this-repo.md).
