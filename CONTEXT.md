# Qmedia Projects Agent

Репозиторий инструкций и скиллов для агента, который отвечает на вопросы о проектах компании по данным сервера `qmedia_projects`. Агенту он доступен только на чтение: ни секретов, ни состояния в нём нет.

## Language

**Проект**:
Строка листа «Проекты» таблицы DEV Timesheet: имя, домен, PM. У одного клиента бывает несколько Проектов под одним доменом — `example.by`, `example.by (ЛК)`, — и это разные Проекты со своими часами и чатами.
_Avoid_: клиент, сайт, заказ, project

**Реестр**:
Список Проектов на сервере — проекция листа «Проекты» вместе со склейкой Источников: какие чаты, названия из таймшита и группа Битрикса относятся к Проекту. Агент в него не пишет; пробел в склейке чинится строкой в листе или названием чата, а не агентом.
_Avoid_: справочник, база клиентов, маппинг

**Источник**:
Откуда сервер берёт данные: Битрикс24 (задачи групп Проектов), таймшит (часы), переписка Telegram (собирает бот через n8n). Сделки CRM Источником не являются — они не подключены.
_Avoid_: система, интеграция, канал

**Пробел**:
Источник, не привязанный к Проекту или ещё не выгруженный. Означает, что данных нет, а не что их значение ноль. Причину показывает `projects_health`.
_Avoid_: ноль, пусто, нет активности

**PM**:
Руководитель Проекта, записанный в листе «Проекты». У Проекта их может быть несколько. Фильтр по PM — часть фамилии.
_Avoid_: ответственный (так Битрикс называет исполнителя задачи), куратор

**Менеджер**:
Сотрудник, который запускает агента: PM или руководитель. Сервер знает его по адресу Google, но агенту этот адрес не виден, поэтому «мои проекты» требуют фамилии.
_Avoid_: пользователь, оператор

**Сотрудник**:
Автор сообщения в переписке с пометкой «(qmedia)». Все остальные авторы — клиент или подрядчик, и сервер их не различает.
_Avoid_: менеджер (это Менеджер, другое), наш
